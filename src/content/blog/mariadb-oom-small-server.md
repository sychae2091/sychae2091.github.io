배포 직후 7분 만에 메모리 알람이 울렸다. 서비스는 정상 동작 중이었지만, 숫자를 보니 아슬아슬했다.

```bash
free -h
#               total   used   free   shared  buff/cache  available
# Mem:          3.7Gi   ...    ...    ...     ...         51Mi
# Swap:            0B
```

**available 51Mi, 스왑 0.** 한 서버에 MariaDB, Java CMS(`-Xmx1024m`), 프론트, node 프로세스가 같이 살고 있었다.

## 1. 누가 먹고 있나

```bash
ps aux --sort=-rss | head -8
```

MariaDB가 약 2.4GB로 압도적이었다. 버퍼 풀 설정을 보니 이해가 됐다.

```sql
SHOW VARIABLES LIKE 'innodb_buffer_pool_size';
```

램 3.7GB 서버에 버퍼 풀 2GB. 전용 DB 서버라면 무난한 비율이지만, 앱이 같이 사는 서버에선 과하다.

## 2. 처음이 아니었다

```bash
dmesg -T | grep -i -E 'killed process|out of memory'
journalctl -k | grep -i oom
```

**이전에 OOM killer가 mariadbd를 죽인 이력이 두 번** 있었다. 지금 떠 있는 프로세스는 그중 마지막 킬 이후 자동으로 재기동된 것이었다. 알람이 처음 울린 것뿐이지, 문제는 몇 달째 진행 중이었다.

## 3. 버퍼 풀 온라인 축소 — 권한의 벽

MariaDB는 버퍼 풀 크기를 재시작 없이 바꿀 수 있다.

```sql
SET GLOBAL innodb_buffer_pool_size = 1879048192;
```

그런데 앱 계정에는 `SUPER` 권한이 없어서 막혔다. 다행히 이 서버의 DB root는 unix socket 인증이라, OS의 sudo 권한으로 들어갈 수 있었다.

```bash
sudo mysql
```

축소는 성공했다. 그런데 `free -h`의 available이 **거의 그대로**였다.

## 4. 줄였는데 왜 안 돌아오나

버퍼 풀을 줄이면 MariaDB 내부적으로는 메모리를 해제한다. 하지만 그 메모리가 **OS로 반환되느냐는 별개 문제**다. glibc의 malloc은 해제된 메모리를 프로세스 안에 쥐고 있다가 재사용하는 경우가 많고, 특히 잘게 쪼개진 영역은 OS로 잘 돌려주지 않는다. 프로세스 RSS 기준으로는 줄지 않은 것이다.

결국 선택지는 재시작이었다. 트래픽이 적은 시간에 **계획 재시작**을 했고, available이 77Mi에서 **1.8Gi**로 회복되면서 알람이 멈췄다.

## 5. 함정: SET GLOBAL은 재시작하면 사라진다

재시작 후 확인해 보니 버퍼 풀이 **원래 값(2GB)으로 돌아가 있었다.** `SET GLOBAL`은 런타임 값일 뿐이라, 설정 파일에 반영하지 않으면 재시작과 함께 증발한다.

```ini
[mysqld]
innodb_buffer_pool_size = 1G
```

메모리가 회복된 건 버퍼 풀이 줄어서가 아니라 **재시작으로 쌓인 메모리가 비워졌기 때문**이다. 시간이 지나면 같은 상황이 다시 온다.

## 근본 대책 정리

| 대책 | 효과 | 비고 |
|---|---|---|
| 버퍼 풀을 설정 파일에서 축소 | 상한 자체를 낮춤 | 재시작 필요, 캐시 적중률 확인 |
| 같은 서버 Java 힙 재조정 | 앱 쪽 상한 정리 | `-Xmx` + 메타스페이스·스레드 몫까지 계산 |
| 스왑 추가 | OOM 대신 느려짐 | 이 서버는 불가했음 |
| DB 분리 | 근본 해결 | 비용·작업량 큼 |

## 배운 것

- **알람이 처음 울린 날이 문제의 첫날은 아니다.** `dmesg`부터 본다.
- 버퍼 풀을 줄이는 건 "상한을 낮추는 것"이지 "지금 메모리를 돌려받는 것"이 아니다.
- `SET GLOBAL`로 고친 건 **설정 파일까지 반영해야 고친 것**이다.
- DB와 앱이 한 서버에 있으면, 각자의 "적정값"을 합친 게 서버 램을 넘지 않는지부터 계산한다.
