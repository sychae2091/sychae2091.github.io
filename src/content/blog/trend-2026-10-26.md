이번 주는 보안 업데이트 주간이었다. Node.js와 Oracle Java가 이틀 간격으로 보안 릴리스를 냈고, Java는 그 뒤로 긴급 알림이 두 번 더 붙었다. 여기에 Spring Boot 패치 릴리스와 GitHub Actions 네트워크 변경까지 정리해 둔다.

## Node.js 10월 보안 릴리스 (22.x / 24.x / 26.x)

**무엇이 바뀌었나**

10월 21일 Node.js가 지원 중인 세 라인에 보안 릴리스를 냈다. 고칠 버전은 **v26.12.1, v24.22.1, v22.23.4**다. 취약점은 10개이고 그중 High가 4개다.

- Brotli 디코더 out-of-bounds write — RCE로 이어질 수 있음 (CVE-2026-111497)
- TLS 호스트명 검증 우회 2건 — 전각 숫자 IP, 앞자리 0이 붙은 IPv4 리터럴 (CVE-2026-105483, CVE-2026-106069)
- `dns.resolve*()` / `dns.reverse()`가 NUL 바이트가 들어간 이름을 잘라냄 (CVE-2026-105482)

공식 공지는 EOL 버전도 같은 문제에 영향을 받으니 지원 라인으로 올리라고 적고 있다. EOL 라인에는 패치가 나오지 않는다.

**실무에서 의미**

- 서버에서 도는 Node 프로세스(배포 스크립트, 프론트 빌드 서버, 사내 툴 백엔드)의 버전을 먼저 훑는다. `node -v`가 위 버전 미만이면 올린다.
- Brotli 압축 응답을 받거나 TLS로 외부 API를 부르는 코드는 영향 범위에 직접 들어간다.
- EOL 버전에 묶인 프로젝트는 이번이 업그레이드 계획을 세울 이유가 된다. 당장 못 올리면 적어도 인터넷에 노출된 서비스부터 분리해서 본다.
- CI 이미지의 Node 버전도 확인한다. `node-version: 24`처럼 메이저만 적었으면 새 빌드에서 자동으로 최신 패치가 잡힌다.

**출처**: [Node.js — October 2026 Security Releases](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases)

## Oracle Java 10월 CPU + eMudhra 인증서 긴급 알림

**무엇이 바뀌었나**

10월 20일 정기 CPU로 **17.0.21, 21.0.13, 25.0.5**(그 외 8u511, 11.0.33, 27.0.1)가 나왔다. 21.0.13 릴리스 노트 기준 주요 변경은 이렇다.

- Symantec, Entrust, Camerfirma 루트를 TLS 서버 인증서용으로 신뢰하지 않음
- JDK 내장 `HttpServer`가 `Host` 헤더가 없거나 중복된 HTTP/1.1 요청을 400으로 거절
- LDAP에서 오는 RMI URL 참조를 기본으로 처리하지 않음
- **JDK 21은 21.0.13부터 라이선스가 OTN으로 바뀜** — 개인·개발 용도는 무료지만, 기존 NFTC로 허용되던 일부 용도는 더 이상 안 될 수 있다고 명시

그리고 바로 뒤에 CVSS 9.1(Critical) 보안 알림이 두 번 나왔다. 둘 다 JSSE 컴포넌트이고 인증 없이 원격으로 악용 가능하다.

- 10월 21일 CVE-2026-91403: eMudhra 관련 중간 CA 인증서를 불신 처리
- 10월 24일 CVE-2026-114820: eMudhra 관련 루트 CA 인증서를 제거 (영향 버전이 `.0.2` 빌드 — 즉 21일 알림을 적용한 버전도 다시 올려야 함)

**실무에서 의미**

- Oracle JDK를 쓰는 서버라면 20일 CPU만 적용하고 끝내면 안 된다. 두 알림이 반영된 최신 빌드까지 확인한다.
- 인증서 불신 처리가 들어갔으므로 업데이트 후 외부 HTTPS 연동(결제, 외부 API 등)이 깨지지 않는지 스모크 테스트를 한 번 돌린다.
- 운영 서버에서 Oracle JDK 21을 쓰고 있다면 라이선스 변경을 확인해야 한다. 이참에 OpenJDK 배포판으로 갈지 정리해 두는 게 좋다.
- 다음 정기 CPU는 11월 17일로 잡혀 있다.

**출처**: [JDK 21.0.13 Release Notes](https://www.oracle.com/java/technologies/javase/21-0-13-relnotes.html) · [Alert for CVE-2026-91403](https://www.oracle.com/security-alerts/alert-CVE-2026-91403.html) · [Alert for CVE-2026-114820](https://www.oracle.com/security-alerts/alert-CVE-2026-114820.html)

## Spring Boot 4.1.2 / 4.0.9 / 4.2.0-RC1

**무엇이 바뀌었나**

10월 23일 세 버전이 동시에 나왔다.

- **4.1.2**: 버그 수정·문서·의존성 업그레이드 126건
- **4.0.9**: 같은 성격으로 99건
- **4.2.0-RC1**: 기본 Buildpacks 빌더가 Ubuntu 26.04 기반(`paketobuildpacks/ubuntu-resolute-builder`)으로 바뀌고, `spring-boot-properties-migrator`가 오류·경고 시 앱 기동을 실패시킬 수 있게 됐다. 실행 jar의 클래스·리소스 조회가 빨라져 기동 성능도 개선됐다.

공지 본문에 보안 수정 언급은 없다.

**실무에서 의미**

- 4.0.x / 4.1.x 프로젝트는 `pom.xml`의 parent 버전만 올리면 되는 패치 릴리스다. 위 Java 업데이트와 묶어서 한 번에 배포하면 테스트 비용을 아낄 수 있다.
- 4.2는 아직 RC라 운영 반영은 이르다. 다만 `properties-migrator`를 실패 모드로 돌리는 기능은 업그레이드 때 쓸 만하니 GA 때 다시 본다.
- Buildpacks로 이미지를 만들지 않는다면(jar + systemd 배포) 빌더 변경은 당장 할 일 없음.

**출처**: [Spring Boot 4.1.2](https://spring.io/blog/2026/10/23/spring-boot-4-1-2-available-now/) · [Spring Boot 4.0.9](https://spring.io/blog/2026/10/23/spring-boot-4-0-9-available-now/) · [Spring Boot 4.2.0-RC1](https://spring.io/blog/2026/10/23/spring-boot-4-2-0-RC1-available-now/)

## GitHub Actions blob 스토리지 엔드포인트 추가

**무엇이 바뀌었나**

10월 22일 GitHub이 Actions용 blob 스토리지 호스트를 추가했다. 새 호스트는 meta API에 반영됐다.

- `productionresultssa30` ~ `productionresultssa49.blob.core.windows.net`
- `productionresultssa100` ~ `productionresultssa199.blob.core.windows.net`

이미 `productionresultssa*.blob.core.windows.net` 와일드카드로 허용하고 있으면 바꿀 것이 없다. 호스트를 하나씩 허용하고 있으면 추가하지 않을 경우 job summary와 로그가 끊길 수 있다고 한다.

**실무에서 의미**

- 방화벽 아웃바운드를 호스트 단위로 막아 둔 환경에서 self-hosted runner를 쓰고 있다면 허용 목록을 확인한다.
- GitHub 호스팅 러너만 쓰는 경우(이 블로그 배포 포함)는 당장 할 일 없음.
- GitLab CI, Gitea Actions와는 무관하다.

**출처**: [GitHub Changelog — Meta API endpoints updated for Actions blob storage](https://github.blog/changelog/2026-10-22-meta-api-endpoints-updated-for-actions-blob-storage)
